# Local editorial review checklist

This screen is an operator stand. It is not yet a hosted competition submission.
Its purpose is to collect evidence of the human work needed to bring A and B to
the same publication standard. A single prepared passage cannot prove general
platform superiority.

1. Enter a stable editor label. It is a self-declared study identifier, not a login.
2. Paste the original and two corresponding passages, or supply an existing
   confirmed scope. Check content coverage and declare one publication standard.
3. Preserve the original files and provenance. Review missing notes and references
   before making quality decisions. A text passage without its external apparatus
   is insufficient to judge the quality of that apparatus.
4. Document previous human work for **each** candidate, including expert editing
   inside Kitabs. Choose unknown when there is no evidence. A historical published
   translation is not an unedited machine-output baseline.
5. Start Editing / research **before** reading, researching, checking references,
   adding tasks or editing. Pause during interruptions. Closing the tab leaves the
   timer running. Use the same label when returning; reload does not erase a session.
6. Select saved text and add a task: meaning, terminology, Quran, hadith, apparatus
   or readability. The task records its exact Unicode range, quote and version.
   These are manual tasks; the UI does not yet import the LLM pilot's findings.
7. Edit the translation and save a new version with a reason. Save requires a
   running editing session for that side. Original text is retained. After a save,
   revisit older decisions: their anchors still refer to the historical text.
8. Resolve or dismiss each task with evidence. Dismissal remains in the record.
   Zero tasks does not certify zero errors. Stop the editing session.
9. Start Final verification for the current version. Check it against the shared
   standard, stop the timer, then explicitly accept the version with a note. Repeat
   for the other candidate. No task may remain open or stale at acceptance.
10. Export evidence JSON. It includes original scope, all text versions, commands,
    actors, intervals, prior work declarations, acceptance and limitations. Keep
    it private when it contains copyrighted or confidential material.

The totals include stopped/paused intervals plus attributed prior work. A live
interval is shown by the running timer and enters the totals on pause or stop.
Only when both candidates are accepted, prior work is known, sessions are stopped
and A's total is positive can the screen show `(A - B) / A * 100`. A negative
result is retained. These are editor-controlled measurements, not attention
detection or independent verification of self-reported history.

Use fresh prospective runs with documented preparation time to measure the whole
pipeline. Historical real samples remain useful for demonstrating findings and
remaining work even when their total time saving cannot be established. For a
stronger study, predefine inclusion rules, counterbalance review order, use several
matched passages and record reviewer differences.

## Before a public jury demonstration

- Add authenticated session ownership and authorization; the present application
  binds to loopback and rejects nonlocal Host headers.
- Attach candidate apparatus and reference provenance to the review and connect
  reviewed model findings without inventing new anchors.
- Verify the judge-family independence requirement; brand masking and a different
  model version alone do not remove shared-family bias.
- Confirm material redistribution rights, supply sources and software licenses,
  freeze the reviewed release SHA and test the installation instructions.
- Provide the final public URL, release, demonstration and submission checklist.
  Discord updates do not replace the official competition submission.
