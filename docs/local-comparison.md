# Локальный стенд Independent Judge

Отдельный репозиторий, без импорта модулей платформы и без доступа к её БД.
Новый экран: оригинал + переводы A/B → проверка границ → сравнение → результат.
По умолчанию принимаются файлы; вставка текста также доступна. Детали замечаний,
источников и методики свёрнуты. Минуты вводить не нужно.

## Установка и запуск

Нужны Python 3.12+ и Node.js 22+. Из корня этого репозитория:

```sh
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.lock.txt
.venv/bin/pip install --no-deps -e backend
npm --prefix frontend ci
```

Первый терминал:

```sh
JUDGE_DATA_DIR=.judge-data/local-comparison JUDGE_ENABLE_LIVE=0 \
  .venv/bin/python -m uvicorn independent_judge.api.app:create_app \
  --factory --host 127.0.0.1 --port 8775
```

Второй терминал:

```sh
cd frontend
JUDGE_API_ORIGIN=http://127.0.0.1:8775 npm run build
JUDGE_API_ORIGIN=http://127.0.0.1:8775 npm run start -- --port 3015
```

Открыть http://127.0.0.1:3015. Серверы доступны только локально. `.env.example`
описывает переменные; приложение не загружает `.env` автоматически — передайте
настройки в окружении процесса. Не используйте каталог данных платформы.

Без настройки модели работают загрузка, извлечение текста, подтверждение границ,
просмотр существующих примеров и проверка их источников. Новым материалам не
присваивается выдуманный результат. Приватные примеры в `.judge-data` не входят
в Git; чистый клон не содержит прежних книг и платных прогонов.

## Автоматический прогноз

Количество кандидатов на исправление и прогноз трудозатрат — разные показатели.
Прогноз использует одинаковые для A/B относительные веса категорий K/T/A/S:
5/3/4/1. Учитываются только однозначно привязанные неспорные замечания; исключения
показаны в деталях. Диапазон чувствительности получен изменением весов, а не
статистическим доверительным интервалом. Веса пока не откалиброваны на редакторах.

Нет оценки или нет знаменателя A → «недостаточно данных», а не 0% экономии.
Отрицательное значение означает больший прогноз для B. Даже 100% не означает,
что текст можно выпускать без чтения. Чтение, проверка источников и работа людей
внутри KITABS не измерены этой формулой. Для конкурсного утверждения о сокращении
общего человеческого времени требуется отдельное исследование; данная версия
не выдаёт прогноз за измеренное время.

## Библиотеки

[Контракты источников](reference-sources.md): поиск кандидатов по арабским
Бухари/Муслиму, прямой адаптер Sunnah.com с ключом. Сверяются цитаты в кавычках
или круглых скобках. Найденная запись сохраняет текст, ссылку, время и SHA-256.
Номер из другого издания не считается подтверждением без сравнения текста.
Нет совпадения ≠ недостоверный хадис. Перевод и религиозное заключение требуют
экспертной проверки. Автоматическая верификация аятов в этой итерации не добавлена.

## Включение живого судьи оператором

Только после разрешения владельца на платные запросы и определения бюджета.
Нужны чистый проверенный checkout, `JUDGE_ENABLE_LIVE=1`, `AI_GATEWAY_API_KEY`,
положительные `JUDGE_BUDGET_TOTAL_USD` и `JUDGE_BUDGET_RUN_USD`.
`JUDGE_CONFIG_PATH` указывает на отдельный приватный JSON со всеми полями
`JudgeConfig`: `model`, `provider`, `max_tokens`, `reasoning_effort`,
`input_usd_per_million`, `output_usd_per_million`,
`reserve_input_usd_per_million`, `price_version`.
Модель и цены нужно проверить перед использованием. Текущий Gateway-адаптер
принимает только уже поддержанный контракт провайдера; смена семейства судьи
требует отдельной проверки адаптера. Независимость от авторов переводов не
устанавливается автоматически и не заявляется как доказанная.

Один подтверждённый набор получает один ID запуска. Повторное нажатие и
перезагрузка страницы не оплачивают его заново. Отключение браузера не отменяет
работу. При перезапуске восстанавливается сохранённый отчёт либо показывается
прерванный запуск; автоматического повтора модели нет. Неудачный запуск требует
разбора оператором. Для одного каталога данных допускается один worker.

## Проверки

```sh
.venv/bin/python -m pytest -q
npm --prefix frontend test
npm --prefix frontend run typecheck
npm --prefix frontend run build
git diff --check
```

Тесты модели выполняются офлайн с подменой только порта провайдера; это проверяет
протокол и сохранение результатов, но не точность реальной модели. Живой Sunnah
API также требует проверки после получения доступа. Публикация и показ жюри
выполняются только после отдельного одобрения владельца.
